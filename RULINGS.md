## Rulings of 2026-10-24 (the first mark was being spent a week early)
1. **Decided - a mark is claimed only by a pull that brought numbers back, and "unpriced" means no props rather than no marks.** The first-sight pull fired as soon as a game appeared in `/events`, up to eight days out, where no book has posted player props; it returned empty, stored nothing and still ticked the mark off, so the rule meant to guarantee every game one number was always spent at the one moment it could not work. An empty answer now claims nothing and never overwrites props already stored (which it previously did, so a bad late pull could wipe numbers Danny was reading). `FIRST_WINDOW` = 48 h bounds the retry to the days a book actually prices, `FIRST_RETRY` = 8 h stops an hourly schedule re-asking hourly. The per-game marks and the LATE tolerance from 2026-10-18 are unchanged. Self-healing: games already holding a spent mark become due again with no migration.
2. **Decided - Sunday mornings get their own cron, `5 10-14 * * 0`.** The early Sunday kickoff (9:30am ET London = 13:30 UTC) needs a run between 10:45 and 13:35 UTC to reach either of its marks, and Sunday had no scheduled run between 05:05 and 15:05 UTC. That game could never get props - arithmetic, not a dropped run. Five slots, redundant on purpose because GitHub drops most of them; ~2 credits a run. **Danny applies this one** (`.github/workflows/` is his, `DEPLOY.md`).
3. **Decided - Jaclyn's bet #12 graded by hand.** Three NFL moneylines from 18-19 October had sat ungraded for six days with no score recorded. All three hit; graded with the repo's own `grade_leg` and settled **won**, $4.92 → $12.82. This fixes the three picks, not the cause: NFL games leave the slate once final (open since row 2), so a score missed in the window is never seen again.
4. **Open - bet #12's stored slip `chance` is wrong** (0.7487, its last pick's chance, where the product of its three picks is 0.3808). Every other bet matches its product exactly, so this is a one-off. It changes the verdict - 0.3808 against a 0.3838 break-even is a **Coin toss** at -0.8¢ per $1, not the **Great** on file - and so changes how History sorts it. Not corrected: the cause is unknown and a record should not be rewritten on a guess. Danny's call.

## Rulings of 2026-10-18, afternoon (prop type filters; the props card redrawn)
3. **Decided - prop types filter in two levels, and the levels are built to grow** (Danny picked "the two-level version" of 3 offered: A pick one, B pick any, C four groups). A group row - **All - Passing - Rushing - Receiving - Touchdowns** - with counts; tapping a group that holds more than one market opens its markets in a second, indented row. Groups are multi-select, so "rush yards + receiving yards, no TDs" is two taps, which single-select could not do. Why two levels and not B's flat row: today's six markets fit one row, but combos, defence and kicking would make it sixteen chips. **One state only** - the set of markets switched on (`PON`); the group chips are derived from it, so the two rows can never disagree. A half-filled group is drawn with a dashed edge; tapping it fills, tapping a full one clears. A market `props.py` ships that the page has never been taught lands in an **Other** group by itself rather than falling off the board, and a group with nothing on today's slate is not drawn.
4. **Decided - the prop type is a heading inside the game card, not a column on every row** (Danny's Excel sketch, the second time a sketch of his set a layout - see ruling 4 of 2026-09-26 evening). The card groups its rows under *Passing Yards*, *Touchdowns (passing)*, *Rushing* and so on, and the per-row Prop column is gone; the table went from six columns to five. **This started as a bug Danny caught:** `props.css` hid `.mk` under 760px but the class was only on the `<td>`, never the `<th>`, so every heading sat one column left of its data - "PROP" over the book's number, "CHANCE" over the Add button. The heading layout removes the column the bug lived in. Two departures from the sketch, both agreed: the book's number stays under **Book** (the heading now carries the prop type), and headings are drawn in the accent so they do not read as another data row.
5. **Decided - Anytime TD opens shut** (Danny picked "collapse Anytime TD to a closed heading you tap to open"). It is 44% of the board and 24 players on a single card, none with a number to type. Three things open it so a row can never hide from a search: tapping the heading, a player search that matches one of its rows, and the Touchdowns chip (asking for them is asking to see them). The tap is remembered per game, not per market, so opening TDs on one game leaves the rest shut.
6. **Decided - a game that is OVER leaves the NFL Props screen** (Danny, 4:47 PM CT: "I'm okay with them showing after kick off, but once the game is over, they shouldn't show up"). After kickoff a card stays - props are still worth reading while a game runs, and Save bet has never refused a started game (ruling 1 of 2026-09-26). Over is different. **Two signals, whichever lands first:** (a) the slate says `final` - props game ids ARE the odds-api event ids the NFL slate carries, so a props card looks itself up in `R.upcoming`, where `nfl.py` already writes `final` off the scores feed; exact, but only as fresh as the last refresh commit; (b) **kickoff + 4 hours** (`PROP_OVER_H` in `props_tab.js`), which needs no data and no refresh, so the board still clears on a night when nothing runs - which is exactly how this was found, with noon games still up at 4:47 PM because the last refresh was 3:11 PM and `props.py` only dropped a game from its store after 8 hours. The store cutoff is now 5 hours, deliberately looser than the page, so the page is what decides what Danny sees. The chip counts, the N-of-M line and the tab badge all count the live board, and a board where everything has finished says so rather than going blank. **Open:** 4 hours is a margin, not a measurement - a weather-delayed game could vanish late if no refresh has run. Signal (a) covers it whenever one has.

## Rulings of 2026-10-17 (props step one gets built)
1. **Decided - props never share a slip with a game pick** (Danny picked "props-only slips" of 3 offered). A props slip is its own thing: its own list, its own payout box, its own verdict. The game slip is untouched, and `grade()` did not have to learn a second kind of pick. Same-game props are allowed and warn, as ruling 5 of 2026-09-27 said.
2. **Decided - one hourly job on game day, per-game marks** (Danny picked this of 3 offered). NFL Sunday kickoffs run 8:30am to 7:20pm CT, so "two hours before kickoff" is a different clock time for every game; three fixed clock times would have left the night game's "fifteen minutes before" pull hours stale. `props.yml` runs hourly on Thu/Sun/Mon and pulls only the games that have reached one of their own marks (a morning sweep, ~2 h, ~15 min). `props.py` records which marks a game has had, so nothing is pulled twice. Cost ~6 credits a game a pull, ~325 a full NFL week.
3. **Proposed - receptions keep the normal; pass TDs go Poisson; rush and receiving yards go lognormal.** This overrides the "receptions get a count shape" line in the mockup Danny approved on 2026-09-27 (ruling 5). The evidence is DECISIONS.md 9: a count shape buys receptions 0.1 points, while Poisson takes pass TDs from 4.1 to 2.3 and lognormal takes rush yards from 5.1 to 2.2. Raised with Danny when it was found, built the evidence-backed way, and left **Proposed** until he confirms, because it changes numbers on a screen he had already signed off.
